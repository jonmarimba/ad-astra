*Real skill, from emilkowalski (a well-known frontend/motion-design engineer). Purpose: guides building web UI that feels physically responsive — Apple's WWDC motion philosophy translated into CSS/JS/spring-based animation (Motion/Framer Motion libraries). Core idea: springs (velocity-aware, interruptible) instead of fixed-duration CSS transitions — animations should start from the CURRENT on-screen value and inherit the user's gesture velocity, not restart from zero. Covers: response directness (feedback on pointerdown not release), interruptibility (never lock input mid-transition), spatial consistency (elements enter/exit along the same path), accessibility (prefers-reduced-motion/transparency/contrast), and typography tracking rules. Relevant if you ever touch the Laurel Park site or the GhOST app idea's UI — same category as the artifact-design skill I load myself for building pages.*
