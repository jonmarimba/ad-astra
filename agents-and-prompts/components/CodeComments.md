# Code comments
- ALWAYS make documentation comments for public functions and properties
- NEVER write comments that describes WHAT the code is doing. The code itself should make it clear enough what is happening. If it doesn't, consider refactoring or variable or function renaming. Instead, comments should describe WHY we are doing what we're doing.
- NEVER include variable values in comments (bad: // changed to 17)
- NEVER add anything about being "co-authored" or written by Claude (or any other LLM) to git commit messages or anywhere in code.
