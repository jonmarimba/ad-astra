# Misc Swift Coding rules
- STRONGLY AVOID the "Stringly Typed" data antipattern. In most cases some combination of enums and/or structs is better. If you find yourself writing code that looks like `if someValue == "some string" { ... }`, stop and consider your choice. While this is sometimes the best or only way, more often it is an antipattern that leads to unexpected behaviors down the road and should be avoided.
- Don't use magic numbers and magic strings. For example, a String value identifier that also has special-case values should usually be turned into an enum with a few cases. A possible exception is when working with data types defined outside our projects (and Swift packages we own). When working with an arbitrary API, however, you can still usually define better types in Swift and craft excellent encoders/decoders instead of keeping magic strings or values.
